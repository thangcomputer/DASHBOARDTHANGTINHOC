## Responsive (checklist)

Breakpoints cần QA tay trên staging: `320–480` (mobile), `576–820` (tablet + sidebar rail), `992–1200` (laptop tabs 1 hàng), `1366–1920` (desktop max-width).

Rủi ro còn lại: table overflow vs `overflow-x-hidden` layout; tab label truncate trên laptop hẹp; sidebar auto-collapse tablet.

## Rủi ro

- Thêm `isAdmin` có thể 403 nếu client non-admin từng gọi API list (GV vẫn dùng `/transactions/teacher/:id` — OK).  
- Rematch SePay có thể double-apply nếu logic match không atomic — hiện vẫn dùng `findOneAndUpdate({ paid: false })` / session `pending` (an toàn tương đối).  
- Rollback payout không phải multi-doc transaction đầy đủ (race vẫn tồn tại dưới concurrent admin).

## Kết luận

Hệ thống đủ “enterprise-lite” về auth defense-in-depth nhưng **authorization trên API nhạy cảm** và **money path** là điểm yếu lớn nhất. Batch Critical/High authz + SePay rematch + scrub deploy secrets đã được áp dụng trong code. **Không nên** coi audit static này là đủ — cần pentest + rotate secret + test regression money trước khi tuyên bố “secure”.

**Điểm tổng: 62/100** — có thể lên ~75 sau khi đóng nốt High còn lại và harden uploads/schedule.
